## A. Intake and Overview

Rows: intake records accepted/linked whose job has `project_owner_id` NULL, not archived, stage not in complete/invoiced/lost/archived. One table line each (quote no., job link, client, spec, value only with jobs.value, won date, PM select). Choosing a name calls the existing `PUT /api/job-records/:id/owner` at once; the line shows "Assigned to X." with Undo for 8 s, then goes. Undo sets the owner to null AND returns the job to the stage it had before the assignment, if the assignment is what moved it (Won to Projects) and it is still there: server-side (a guarded `undo` on the same PUT, same user, within 60 s), audited, not a client-side stage write. Who may not set the owner sees text. Keep the two existing decision rules: multi-match records stay in "Waiting for a person". Counts and `data-cc-badge` still work; phone layout stacks each row.

Stage rules, locked stages, value visibility (jobs.value), materials-ordered read-only and archived keep exactly today's behaviour. A new job (no id) keeps today's full form. Archived sits in Links and notes. Two columns, one under 720 px. `people` stays below. Nothing else in job.js reads form inputs after this without working in read mode (check `inputs.`). Whatever the current job carries in print keeps printing.

## B. Quote tab PDF (Crosscuts side; wire format is section D)

Table `joinr_quote_pdfs(intake_id PK -> joinr_intake, quote_id, file, size, sha256, fetched_at, last_attempt_at, last_error)`. `lib/joinr-pdf.js`: fetches with the stored base and key (Authorization header only, `redirect: "error"`, 30 s timeout, max 20 MB, must be `application/pdf` and start `%PDF-`); file directly in uploads/files with a name the NAS backup copies (`names.FILE_NAME_RE`), temp file then rename, replaced only after a good fetch. Fetched on first view, again when the intake payload's `quoteId` or the record changed since `fetched_at`, or on Refresh; one attempt a minute per job; 429 honours Retry-After. A failure keeps the old copy and says so. 401/404/503 read as "Joinr doesn't offer the PDF yet." Never log or store the key.
Routes: `GET /api/job-records/:id/joinr-quote/pdf-status`, `GET .../joinr-quote/pdf` (inline; `?download=1` attachment; nosniff, private no-store), `POST .../joinr-quote/pdf/refresh`. The PDF shows prices: all three need jobs.view AND jobs.value (403 otherwise). UI (`jobquote.js|css`, the joinr and fullquote sections of job.html): PDF in an iframe filling the tab, facts line, Refresh / Download / Open in Joinr; breakdown and "From Joinr" folded below, "From Joinr" opening itself when it has a change to acknowledge. Without jobs.value or with no PDF: breakdown open, plain sentence. On phones: an Open PDF button instead of an iframe. Print hides the iframe. `ci/fake-joinr.js` gains quote-pdf; new smoke `ci/smoke-jobpage-quotepdf.sh`.

## C. Orders & materials

Migration 067 (all additive; B's table is in it): `job_materials` gains `suggested TEXT NOT NULL DEFAULT '[]'` (JSON list of field names still suggested), `prefilled_at TEXT`, `skip_order INTEGER NOT NULL DEFAULT 0 CHECK (skip_order IN (0,1))`; table `material_section_suppliers(section TEXT PRIMARY KEY, supplier TEXT NOT NULL, updated_at, updated_by)`.
- **Prefill** (`lib/materials.js`): fills only empty supplier/brand/code/colour/finish on live, unordered lines with `prefilled_at` NULL. History first: the most recent other job line with the same section and case-folded trimmed name that has a supplier AND has a live order (sent or ordered); all its details come together. Else the section default supplier. Sets `suggested`, `prefilled_at`. Editing a field drops it from `suggested`; a field a person clears is never refilled. Runs after every fillFromJoinr and manual create, and by `POST /materials/prefill` (jobs.edit), which the page calls on open when lines lack `prefilled_at`. Never runs while the latest revision is current and unchanged (it would change its fingerprint). `fillFromJoinr` still never touches a person's fields.
- Joinr `drawers` lines get `skip_order = 1` at first prefill (they are on the drawer order). `skip_order` lines are left out of liveLines for finalise, problems, fingerprint and send, and listed at the foot under "Not in this order" with Include; other lines have "Leave out". Two-pac from Joinr arrives as qty 1, unit "job". Other text-only lines keep no quantity and read "Needs quantity".
- **Section defaults**: `GET/PUT /api/material-section-suppliers` (GET jobs.view, PUT users.admin), edited on the Users admin page beside the other settings.
- **Send**: `GET /api/job-records/:id/project/send-preview` (jobs.view): lines, ready, problems, suppliers, next revision, requested install, whether a deposit will be raised and the board week (reuse handoffs/invoices rules, read-only), fingerprint, and why it cannot be sent. `POST /api/job-records/:id/project/send-now` {fingerprint}: needs jobs.edit AND orders.edit; one transaction: 409 if the fingerprint differs, finalise if the list changed or has no revision, then the existing `send()`; any refusal rolls everything back. No rule is duplicated.
- **Page** (`jobmaterials.js|css`, materials and orders sections of job.html, orders part of job.js): as mockup D. Inline editing saves on leaving the field; Details shows the joined text and opens four small fields. The old "Create order lines" bar goes from the page (API stays). After sending: progress grouped by supplier; editing, ordering, receiving, drawers and the manual add-line still available. Send confirms in a `cc-dialog`. Print page and project page still work (they share the lib).
- New smoke `ci/smoke-jobpage-materials.sh`; update m18/m22 smokes only where behaviour is meant to change, never to hide a failure.

## D. Wire contract version 5 (Joinr, approved twice by Todd 2026-11-23, local branch only)

`GET {base}/api/integrations/crosscuts/quote-pdf?quoteId={uuid}`, Authorization Bearer, the same two credentials and order of checks as open-quotes. Exactly one parameter. 200: `application/pdf`, the same bytes the portal's quote PDF route renders (same loader model and renderer), `private, no-store`, nosniff. Only a quote of the key's own org that is currently won and not deleted. 400 bad/missing/extra parameter (only after a live key), 401 dead key, 404 not found or not won (one answer), 429 with Retry-After (own per-key limit, 12 a minute), 503 otherwise. GET/HEAD/OPTIONS only as the sibling routes. A read-only SQL function in one additive migration. The doc `docs/integrations/joinr-crosscuts-intake.md` goes to version 5 identically in both repos.
